> **Kraken Air (XX) and Wyvern Overseas Airways (YY) are fictional airlines**, and their codes
> belong to no real carrier. Every document the model will read in this course — fare rules,
> bulletins, call-centre texts — is synthetic, written for teaching. No real airline system, customer or
> production data is used anywhere in this repository. This is the site's full statement; every
> other page carries the short reminder in its footer.

## 3 things to install before we start

The whole practical part is one small repository you clone, two containers you start, and a
request collection you click through. Install these three and pull the two models — ideally
beforehand: the models are 4.5 GB, and starting on the office network in the morning will not be
done by 09:10.

| | Why | Get it |
|---|---|---|
| **Ollama** | runs the two models on your laptop — nothing leaves the machine | [ollama.com/download](https://ollama.com/download) |
| **Podman Desktop** | runs ChromaDB and the lab's API as containers | [podman-desktop.io](https://podman-desktop.io) |
| **Bruno** | the request collection that is the day's handout | [usebruno.com/downloads](https://www.usebruno.com/downloads) |

No API key, no cloud account, no sign-in, no Python. [Before we start](/modules/00-setup/) walks
every step and ends on one request that says `ready`.

## The rule this course is built on

No concept is introduced before you have **seen the failure that requires it**. Each module opens
on the previous one's wall; module 2 is the one declared exception, and says so on its own page.

| Stage | What broke |
|---|---|
| **1 · The bare LLM** | It answers about our airline, confidently, with no source — and it is wrong |
| **2 · What a weight is** | A weight is a frozen photograph of the training data |
| **3 · Fine-tuning** | We can re-take the photograph with our data — and it is of last quarter, and it cites nothing |
| **4 · The data moved** | Put the whole rule book in the prompt: it fits, and you pay for the whole book on every question |
| **5 · Simple RAG** | Hand it the right piece: the answer is grounded — now look at what was actually retrieved |
| **6 · ChromaDB** | The chunks are visible, and the one with the number has lost its header |
| **7 · Chunking and noise** | Cut at the document's own structure: same model, same store, right answer |
| **8 · Freshness** | Re-ingest last quarter's edition and this quarter's: 120 → 90 with no retraining |
| **9 · Closing** | Rewind the chain |

## How the day runs

- **Theory** (modules 2 and 3) — the trainer drives from the projector; you run nothing.
- **Practice** — the page names a folder and a request in **Bruno**; you send it, and the response is the lesson. Each request's *Docs* tab says what to look for.
- **Three surfaces** — Bruno · a terminal at the root of `kg-rag-lab` · Podman Desktop. Every command block says which one it belongs to.

Retrieval quality numbers (`hit@1`, `recall@5`) are measured by the trainer and quoted where they matter; nobody in the room runs a benchmark.
